## 复现的问题

1. 网页显示制造商 `0x7099…79C8`，MetaMask 已选择零售商 `0x3C44…93BC`，但该账户对当前网站显示“未连接”。钱包内点击“连接”后，网页收到 `accountsChanged` 并清空旧连接；点击网页 `Connect wallet` 后地址一致。消费者、服务中心和二手消费者首次使用时也需要连接网站。原指南只写切换账户、点击网页按钮，遗漏此步骤。
2. `Contract address` 输入框误填成制造商钱包地址，而当前生效配置仍是部署所得合约。切换角色时应使用同一合约，账户地址应填在组员或收件人字段。
3. 制造商尝试授权零售商时，页面显示 `unknown custom error` 和 `0x7bfa4b9f`。使用服务中心复现相同报错，确认 `id("NotAdmin()").slice(0, 10)` 等于该值；合约权限检查正确，但界面没有解释恢复方式。本地脚本原本已经配置演示角色，无需重复授权。

## 修复与复测

- 连接配置在调用 `admin()` 前检查合约代码；钱包地址误填时提示使用部署所得地址，并保留原生效连接。
- 角色操作读取 `admin()`，与本次实际签名账户比较；账户不符时显示管理员及签名者完整地址，不再尝试发送角色交易。合约仍执行最终权限校验。
- 工作台及操作指南补充 MetaMask 当前网站的账户连接步骤、地址核对、本地预授权角色和模拟 gas 说明。
- 新增三个组件回归场景，修复前失败，修复后通过；全量网站测试 43 项通过，TypeScript、生产构建、工作区链接及 `git diff --check` 通过。
- 同一个用户浏览器中复测：二手消费者点击 `Grant role`，得到 `Switch to administrator wallet ... Current signing wallet: ...`；钱包地址误填得到 `No contract code ...`。恢复正确配置后重新查询，产品及理赔历史仍完整。
