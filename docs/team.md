# 五人分工与里程碑

以下 A–E 是待填姓名的责任位，每人有独立可合并产物和报告/演示职责。先在任务中填写实际姓名或 GitHub 用户名，再由组长登记小组。

| 人员 | 主责与可交付代码 | 报告/演示职责 | 交接对象 |
| --- | --- | --- | --- |
| A：合约/资产 | 产品注册、角色权限、转手及事件；相应单元/负面用例 | 数据模型、权限、转手演示 | 向 B/C 提供接口和事件字段 |
| B：合约/保修 | 保修状态机、理赔、审批、维修事件、时间/额度边界测试 | 安全分析、gas 记录、理赔演示 | 与 A 冻结合约接口，向 D 提供状态定义 |
| C：前端/溯源 | 钱包连接、注册/转手界面、真实性查询和所有权时间线 | 架构图、溯源演示 | 与 A 对齐交易和查询接口 |
| D：前端/保修 | 申请/审批/维修界面、错误和等待状态、键盘可用性、前端验收用例 | 可用性与可访问性章节、保修演示 | 与 B 对齐状态和事件 |
| E：集成/交付（建议组长） | 部署与初始化脚本、CI、跨模块烟测、干净环境安装验证、源码打包 | 安装与成本章节、报告/幻灯片统稿与计时 | 汇总 A–D 的可复现证据 |

每位成员还需复核一位其他成员的 PR；跨合约/前端接口变更至少由受影响的另一负责人复核。E 负责集成，不代替 A–D 为其功能签收。报告正文由各负责人先写自己的章节，E 统一结构和引用；全体参加 10–12 分钟彩排。

## 依赖与建议节点

1. **即刻**：确认方案和四项业务规则；填写 A–E 姓名，A/B 给出接口草案，C/D 给出页面流程，E 建立任务。
2. **2026-11-01 前**：指定组长并完成课程要求的登记。
3. **第一轮实现**：A/B 交付合约和本地部署；C/D 用冻结接口连通主要页面；E 在干净环境跑通安装。
4. **第二轮验收**：按 [AC01–AC13](acceptance.md) 完成测试、负面路径和现场流程，记录 gas 与安全取舍。
5. **2026-12-01 23:59:00 前**：完成 ≤30 页报告、幻灯片、10–12 分钟彩排和符合命名的源码 ZIP，由组长提交。

课程未给演讲的具体日期；以教学安排公布的最后一课为准。以上轮次是内部顺序，不冒充课程硬性截止日。
